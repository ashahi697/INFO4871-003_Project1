# INFO4871-003_Project1
Project 1 for INFO 4871, building a web application that can be used for a reading application

Instructions:
In this project, the overarching learning objective is to transform a customer specification for a web application into a functional design mock-up. You will create this mock-up using HTML and CSS.

The scenario for this project is as follows: suppose that you are a freelance web developer who is approached by a new customer. The customer wants you to build a bookstore web application for them. By looking at other book-related web applications, the customer has determined that they want the following in the web application:

Book genre pages based on Goodreads's genre page design
Book pages based on Bookshop.org's book page design
Blog post pages based on B&N's blog post page design
When you're building your own design based on the above designs, consider: what are the components of this page, starting with larger components and working down to smaller ones? For example, you might identify that one of the pages has two primary columns, each of which contains smaller components such as a gallery of books or a section of links. Note that all of the HTML and CSS that you write must be entirely your own; you're only basing your designs on the pages above, not copying how they were implemented on those websites.

The customer wants your mocked-up pages to have all of the same components as the pages that they are based on except for the header and the footer. Instead, your mock-up should have a custom header of your own design that is consistent across all of the pages and has links to your mock-up for each page. (You do not need a footer, but you can add one if you'd like.) In addition, the customer would like you to add a homepage to your design mock-up, but they are leaving the design of the homepage up to you — feel free to be creative!

Importantly, note that the customer is not expecting to see actual content (such as images of books or written summaries of them) in your design mock-up; for example, you can use solid-color boxes instead of images and lorem ipsum dummy text where you need it. Just be sure to use real text where needed to distinguish between components (e.g., if a button is supposed to add a book to the cart, label the button "Add to cart", not "My cool button"). Interactive features such as buttons are not expected to actually do anything when clicked on, but they should be present in your mock-up. The only links that need to work are the ones in your header, as specified in the previous paragraph.

Your submission should be an archive file (such as a ZIP file) containing your website files. I am expecting to be able to download your submission, unzip the file, and then launch a Python web server from the unzipped directory (like we did with the Web Website on the first day of class). It is your responsibility to make sure that what you submit contains a working website; if you have questions about the format, ask me well in advance of the submission deadline. Remember that you also must submit via the Canvas submission portal prior to the deadline; late submissions as well as emailed submissions or submissions attached to comments in Canvas will not be accepted.

Remember: you are not being graded on the submission itself. I will be looking at your submission to see if you made a reasonable attempt, and provided that you did, your grade for the project will be based entirely on the writeup that you will complete in class about your project. In other words, it is perfectly okay if your project isn't perfect as long as it reflects your own work and a reasonable amount of effort. If you have questions about whether your project will be sufficient, feel free to ask.
